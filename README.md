# miaopanel-netq

喵喵面板插件 · **网络质量** —— 打开即测，看 VPS 到用户、以及中国大陆到服务器的真实网络状况。

纯前端实现：**没有二进制、没有常驻服务、不需要编译**。

## 它回答三个不同的问题

| 区块 | 回答什么 |
|---|---|
| **线路判断** | 这条线路是优化线路、普通机房，还是绕路？ |
| **我的连接** | 你当前浏览器到服务器的下行与往返延迟 |
| **中国大陆到服务器** | 阿里云 / 腾讯 / 百度节点的实际延迟 |
| **国际对照** | Cloudflare / jsDelivr，用来对比国内是否更优 |

点一次「开始检测」，约 15 秒出结果。**没有任何配置项。**

## 为什么分三块

「服务器出口快不快」「你到服务器快不快」「国内用户到服务器快不快」是三个不同的问题。

只看一个数字会误导：服务器出口 200 Mbps，国内用户照样可能 300 ms 延迟；
反过来延迟很低，也可能是被限速的小水管。

## 线路判断口径

| 结论 | 触发条件 |
|---|---|
| 优化线路特征 | 延迟 < 100 ms 且 抖动 < 12 ms 且 丢包 < 5% |
| 常规机房 / 云主机 | 延迟 < 200 ms，无明显专线特征也无明显劣化 |
| 普通线路 + 明显抖动 | 抖动 > 50 ms 或 丢包 > 10% |
| 远距离绕路特征 | 延迟 > 300 ms（带宽可能很大但体验不稳） |
| 连通性差 | 国内测点平均丢包 > 34% |

> **这是特征推断，不是线路认定。** 要确证 CN2 GIA 之类，得在服务器上跑 `mtr -rwz` 看 AS 路径。
> 插件不会假装自己知道。

## 能测到 / 测不到

- ✅ 你当前浏览器到服务器：延迟、下行、丢包
- ✅ 你所在网络到国内节点：延迟
- ❌ 全国各地用户到服务器的平均延迟（需要商业探针网络）
- ❌ 线路的实际 AS 路径（需要 MTR，浏览器做不到）

## 安装

插件需经喵喵面板开发者后台审核上架，通过后在面板「插件」页一键安装。

本地开发/调试可用打包脚本生成 zip，再走 `/dev/plugins/{id}` 上传：

```bash
node tools/sign.mjs netq 1.1.0 dist/netq-1.1.0.zip
```

## 开发约定（踩过的坑）

写喵喵面板插件时遇到过这些服务端校验，记下来省得重复踩：

1. **`files:` 权限必须是字面绝对路径**，不接受 `${MP_DIR}` 之类占位符。
2. **插件不允许声明写面板目录**（`/www/server/panel` 及所有子目录）。插件文件由面板自己解压放置，
   安装脚本不该往里写东西——本插件的 `install.sh` 只做自检，不写任何文件。
3. **zip 根目录必须带 `manifest.json`**。
4. **zip 内嵌的 manifest 不能自引用**：不要在里面写 `artifact.sha256` 为 zip 自身哈希，
   那是个解不开的固定点。本项目的做法是内嵌版去掉 `artifact` 与 `dev_sig`，
   这两项只放在外传的 manifest 里。

## 隐私

全部测量在浏览器内完成，不上传任何数据。选中的测点（阿里云 / 腾讯 / 百度 / Cloudflare / jsDelivr）
只会收到一次普通的 HTTPS 请求。
